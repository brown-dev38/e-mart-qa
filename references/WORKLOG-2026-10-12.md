## 4. Auth + หน้า Login

- `lib/auth.ts` — next-auth **Credentials provider** + ตรวจ `username` / `bcrypt.compare` / `isActive` + role ใน token/session
- `lib/prisma.ts` — PrismaClient singleton (adapter `PrismaMariaDb`)
- `app/api/auth/[...nextauth]/route.ts` — route handler
- `types/next-auth.d.ts` — augment Session/User/JWT (เพิ่ม `id`, `role`)
- `proxy.ts` (middleware ใหม่ของ Next 16) — ป้องกันเส้นทางด้วย `getToken`:
  - `/` ไม่มี session → 307 ไป `/login?callbackUrl=/`
  - `/login` มี session → 307 ไป `/`
- `app/login/page.tsx` + `app/login/login-form.tsx` — หน้า login (ออกแบบ: split two-plane, ครบสถานะ)
- `app/page.tsx` — หน้าแรกต้องล็อกอิน, `app/sign-out-button.tsx`
- `next.config.ts` — `serverExternalPackages: ["@prisma/client","bcrypt","mariadb"]`
- `.env` — เพิ่ม `NEXTAUTH_SECRET` (random) + `NEXTAUTH_URL`

**บั๊กสำคัญ**: ใน production build (Next 16 + Cache Components) การเรียก `redirect()` ระหว่าง render ของ blocking route ให้ **error page (200 + `__next_error__`)** แทน 307 (dev ปกติ) → จึงย้าย redirect ไป `proxy.ts` และใช้ `export const instant = false` บน `/` (ยังต้องใช้ cookies)

## 6. ผลตรวจสอบ

- `npm run build` + typecheck ผ่านตลอด
- สีใหม่เข้า compiled CSS (เจอ `#016d53` 15 จุด, ไม่เหลือ `#0f6b62`), คอนทราสต์ขาวบน accent ≈ 6.3:1
- หน้า `/login` (prod): มี logo `<img>` ถูก optimize เป็น `/_next/image?url=%2Flogo.png`
- Login flow (prod):
  - `/` ไม่มี session → 307 → `/login?callbackUrl=%2F`
  - login `admin`/`test123` → 200 + session cookie, session ได้ `role=admin`
  - `/` มี session → 200 (หน้าแรก)
  - รหัสผ่านผิด → 401 CredentialsSignin (ไม่มี session)
  - `/login` มี session → 307 → `/`

## 9. ยังไม่ได้ทำ / หมายเหตุ

- คำเตือน `MODULE_TYPELESS_PACKAGE_JSON` ตอนรัน seed — ไม่มีผลกระทบ (optional: เพิ่ม `"type":"module"`)
- Prisma CLI โชว์ "update available 8.0.0-rc.22" — ให้ข้าม (ตั้งใจอยู่บน v7 stable)
