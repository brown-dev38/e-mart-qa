# การลบเอกสารคุณภาพและ Audit log

เปิดใช้ 24 ตุลาคม 2569

## ลบเอกสารคุณภาพ

ผู้ดูแลระบบเปิด **การจัดเอกสารคุณภาพ → ลบเอกสารคุณภาพ** ค้นหารหัสหรือชื่อเอกสาร เลือกรายการ กรอกเหตุผล และพิมพ์รหัสเอกสารหลักเพื่อยืนยัน

การลบเป็นการนำออกจากรายการใช้งาน (`deleted_at`, `deleted_by`, `deletion_reason`) ไม่ลบทะเบียน ไฟล์ ฉบับเอกสาร หรือประวัติออกจากฐานข้อมูล:

- รายการจะไม่ปรากฏในหน้าเอกสารคุณภาพทั้งหมด หน้าตามหน่วยงาน และคิวรออนุมัติ
- ไม่สามารถแก้ไข สร้างฉบับใหม่ ส่งตรวจ หรืออนุมัติเอกสารที่ลบแล้วได้
- ผู้ใช้งานทั่วไปเข้าถึงรายละเอียดและ download handler ของเอกสารที่ลบแล้วไม่ได้
- admin ดูประวัติและไฟล์ได้จากแท็บ **เอกสารที่ลบแล้ว → ประวัติ / ฉบับ** ไม่มีปุ่มกู้คืนหรือทำลายไฟล์ถาวรในรุ่นนี้
- สำเนาร่าง 000 ของแต่ละรอบส่งตรวจยังอยู่ พร้อมไฟล์ ผู้ส่ง ผลตรวจ และเหตุผลส่งกลับ ตรวจได้จากหน้าประวัติฉบับเดียวกัน
- รหัสและลำดับที่ลบไปแล้วไม่ถูกนำมาใช้ซ้ำ
- เหตุผล ผู้ดำเนินการ และสถานะขณะลบถูกบันทึกใน Audit log ภายใน transaction เดียวกับการลบ
- ระบบล็อกทะเบียนและตรวจว่าข้อมูลยังตรงกับรายการที่ admin เปิดไว้ หากมีการแก้ไขหรืออนุมัติระหว่างนั้น ต้องรีเฟรชก่อนยืนยันลบใหม่

ไฟล์เก่าที่เคยเก็บใต้ `public/uploads` ยังเข้าถึงได้ผ่าน static URL เดิม การลบนี้บล็อกผ่านหน้าระบบและ download handler ส่วนไฟล์ใหม่ใน `storage/qa-documents` ไม่เผยแพร่ตรงผ่าน public

## Audit log

เปิด **ตรวจสอบระบบ → Audit log · ประวัติการทำงาน** เฉพาะ admin ที่บัญชีและบทบาทยังเปิดใช้งาน ค้นหาได้จากชื่อบัญชี รหัสบัญชี รหัสรายการ และรายละเอียด กรองประเภทข้อมูล การดำเนินการ ผล และช่วงวันที่ โดยใช้เวลาประเทศไทย ตารางแบ่งหน้า 20 รายการ กด **ดูประวัติ** เพื่ออ่านรายละเอียดเพิ่มเติม

| ขอบเขต | เหตุการณ์ที่บันทึก |
| --- | --- |
| เอกสารคุณภาพ | สร้างทะเบียน สร้าง/แก้ร่าง ส่งตรวจ ส่งกลับ อนุมัติ และลบ |
| เอกสารตามงาน | เพิ่มไฟล์เอกสารและลบเอกสาร |
| ข้อมูลพื้นฐานและข้อมูลการศึกษา | เพิ่ม แก้ไข ปิด/เปิดใช้งาน และลบ ผ่านหน้า admin |
| ผู้ใช้ สังกัด และตำแหน่ง | เพิ่ม แก้ไข เปลี่ยนบทบาท/สถานะ ตั้งรหัสผ่าน และลบรายการที่ระบบรองรับ |
| การเข้า–ออกระบบ | เข้าสู่ระบบสำเร็จ/ไม่สำเร็จ และออกจากระบบ |

ประวัติบันทึกชื่อบัญชีและ ID ขณะดำเนินการ ไม่เชื่อม FK ไปยังบัญชีหรือรายการต้นทาง จึงไม่สูญหายเมื่อเปลี่ยนชื่อบัญชีหรือลบข้อมูลต้นทาง ไม่มีหน้าจอแก้ไขหรือลบ Audit log

ไม่เก็บรหัสผ่าน ยืนยันรหัสผ่าน password hash เลขบัตรประชาชน session token หรือเนื้อหาไฟล์ใน Audit log การตั้งรหัสผ่านเก็บเพียงธง `passwordChanged` รายละเอียดที่บันทึกใช้รายการฟิลด์ที่อนุญาตเท่านั้น และแสดงค่าที่ส่งมาบันทึก ไม่ใช่ประวัติ diff ทุกคอลัมน์

ผลการทำงานมีสามค่า:

- `SUCCESS`: ดำเนินการสำเร็จ
- `FAILED`: คำขอไม่สำเร็จหรือถูกปฏิเสธสิทธิ์ในส่วนที่บันทึกความพยายามไว้
- `STARTED`: เริ่มดำเนินการแต่ยังไม่ยืนยันผล อาจกำลังทำงานอยู่ หรือ process หยุดก่อนบันทึกผล ต้องตรวจรายการต้นทางก่อนลองทำซ้ำ

เหตุการณ์เอกสารคุณภาพบันทึกพร้อมข้อมูลใน transaction เดียวกัน ส่วนหน้าจัดการเดิมบันทึกความพยายามก่อนเรียกงาน ถ้าบันทึกประวัติเริ่มต้นไม่ได้จะไม่เปลี่ยนข้อมูล และหากบันทึกผลสุดท้ายไม่ได้จะคง `STARTED` ไว้ การบันทึกเหตุการณ์ authentication ไม่ทำให้การเข้า–ออกระบบล้มเหลวหากระบบประวัติมีปัญหา โดยแจ้งข้อผิดพลาดไว้ฝั่ง server

Audit log ติดตามการทำงานผ่าน application ตั้งแต่เปิดใช้ ประวัติการตรวจเอกสารเดิมถูกนำเข้าจาก `docs_qa_review_events` เท่านั้น ไม่มีการสร้างเหตุการณ์ย้อนหลังที่ไม่เคยบันทึก การแก้ SQL โดยตรง seed สคริปต์ภายนอก และการอ่าน/ดาวน์โหลดทั่วไปไม่ได้อยู่ในประวัตินี้
